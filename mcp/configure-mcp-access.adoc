= Configure Entra ID and MCP access for AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
Register AI Data Engine in Microsoft Entra ID, add redirect URIs for your AI clients, and set up Entra ID as an identity provider in AI Data Engine. Governed AI access uses Entra ID to authenticate users, and the scopes that you include for each collection determine which collections a user can work with through the Model Context Protocol (MCP).

== Before you begin

* You have a Microsoft Entra ID tenant and a role that lets you register applications and grant consent in that tenant, such as Application Administrator or Cloud Application Administrator.
* You must have the _AI Data Engine administrator_ role.
* AI Data Engine is deployed and has scanned at least one data source. Refer to link:../data-sources/connect-data-source.html[Connect a data source].
* The MCP server has a host name that AI clients can reach over HTTPS, and the host name is on a domain that is verified in your Entra ID tenant. Refer to link:prepare-mcp-host.html[Prepare the MCP host].

== How MCP access works

AI Data Engine doesn't issue tokens and doesn't hold a secret. It validates the Entra ID access tokens that AI clients present. When a user connects an AI client, the user signs in with Microsoft Entra ID, and Entra ID issues an access token for the AI Data Engine application. AI Data Engine checks the token against your Entra ID tenant and lets the client work only with the collections whose granted scopes match.

You register one dedicated application in Entra ID for governed AI access. The same application defines the Application ID URI, the scope, and the app role, and its Application (client) ID is the client ID that you enter in NetApp Console and in your AI clients.

Microsoft Entra ID is the only identity provider that AIDE governed AI access supports.

You grant access at the collection level. Grant each scope access only to collections that its users are allowed to search.

You'll complete these tasks:

. Register an application for AI Data Engine in Microsoft Entra ID and expose its API.
. Define the `power_users` scope and the power-user app role, and assign the app role to your users.
. Add redirect URIs for your AI clients and allow public client flows.
. Set up Microsoft Entra ID as an identity provider in AI Data Engine.
. Configure each collection for MCP by selecting identity providers and user scopes, and then copy the connection details for your AI client.

An Entra ID administrator completes the Entra ID tasks manually in the Microsoft Entra admin center. NetApp Console doesn't create or change Entra ID app registrations.

[#register-the-ai-data-engine-application]
== Register the AI Data Engine application

Complete this task once per tenant. If an AI Data Engine app registration already exists in your tenant, use it.

NOTE: These steps are subject to change based on changes to the Microsoft Entra ID UI. The essential configurations remain the same.

.Steps

. In the Microsoft Entra admin center, go to *App registrations* and select *New registration*.
. Enter a name, such as `NetApp AI Data Engine MCP`, select *Single tenant only*, and select *Register*. Use an application that is dedicated to AI Data Engine governed AI access.
. On the *Overview* page, record the *Application (client) ID* and the *Directory (tenant) ID*. You enter both values in NetApp Console, and you use the Application (client) ID as the client ID in your AI clients.
. Open *Manifest*, set `requestedAccessTokenVersion` to `2`, and save. AI Data Engine accepts only v2.0 access tokens.
. Open *Expose an API* and select *Add* next to *Application ID URI*. Enter `\https://<host>/mcp/tools`, where `<host>` is the MCP host name that you set up in link:prepare-mcp-host.html[Prepare the MCP host], and save. Record this URI; AI clients use it to build the scope that they request.
+
The domain of the host name must be verified in your Entra ID tenant. Entra ID accepts an Application ID URI only on a verified domain.
+
NOTE: If Entra ID rejects the URI with the error `Failed to add identifier URI`, make sure that `requestedAccessTokenVersion` is set to `2` and that the domain is verified in your tenant, and then try again.

[#define-scopes-and-the-power-user-app-role]
== Define the scope and the power-user app role

AI Data Engine recognizes the `power_users` delegated scope. You define the scope and the app role on the AI Data Engine application registration in Entra ID. They don't map to a NetApp Console role, and the scope and app role names must match exactly, including the plural form.

The `power_users` scope requests a power-user session. A power-user session can search file metadata in the collections that you grant the scope access to, list tags, create tags, and add tags to or remove tags from files. AI Data Engine grants a power-user session only if the user also holds the `AIDEPowerUsers` app role.

The full scope value that AI clients request is the Application ID URI and `/power_users`: `\https://<host>/mcp/tools/power_users`. AI clients must request this exact value.

.Steps

. In *Expose an API*, select *Add a scope* and add the `power_users` scope:
* *Who can consent*: *Admins and users*, or *Admins only* to restrict consent
* *Admin consent display name*: `Access AIDE as a Power User`
* *Admin consent description*: `Allows the app to access NetApp AI Data Engine as a power user on behalf of the signed-in user.`
* *User consent display name* and *User consent description*: If you select *Admins and users*, enter text that users see when they consent.
* *State*: *Enabled*
* Select *Add scope*.
. Optional: To skip the consent prompt for users, under *Authorized client applications*, select *Add a client application*, enter the Application (client) ID of this application, select the `power_users` scope, and select *Add application*.
. Open *App roles* and select *Create app role*:
* *Display name*: `AIDE Power Users`
* *Allowed member types*: *Users/Groups*
* *Value*: `AIDEPowerUsers`
* *Description*: `Grants power-user sessions in AI Data Engine.`
* Select *Do you want to enable this app role?*, and then select *Apply*.
. Go to *Entra ID* > *Enterprise apps* > *All applications*, open the AI Data Engine application, and select *Users and groups* > *Add user/group*. Select the users or groups who use governed AI access, select the `AIDE Power Users` role, and select *Assign*.

To assign the app role to groups instead of individual users, your tenant needs Microsoft Entra ID P1 or P2. Assignment to a group doesn't apply to the members of nested groups.

IMPORTANT: Assigning the app role, not only defining it, is required. A user who doesn't hold the app role doesn't get a power-user session.

.How power-user sessions work

A user gets a power-user session only when both of these are true:

* The user holds the `AIDEPowerUsers` app role.
* The AI client requests the `power_users` scope.

If a client requests `power_users` for a user who doesn't hold the role, AI Data Engine doesn't start a power-user session for the user.

[#add-redirect-uris-for-ai-clients]
== Add redirect URIs for your AI clients

Add the redirect URIs that your AI clients use to the AI Data Engine application, and allow public client flows. AI clients sign in with the AI Data Engine application's Application (client) ID. They use PKCE, so you don't create a client secret.

.Steps

. In the Microsoft Entra admin center, open the AI Data Engine application and go to *Authentication*.
. Select *Add a platform* > *Mobile and desktop applications*, and add the redirect URIs for the AI clients that you use. Add one URI for each callback that a client uses:
+
[cols="1,2",options="header"]
|===
|Client |Redirect URI

|Claude Code
|`\http://localhost:8080/callback` and `\http://127.0.0.1:8080/callback`

|Cursor
|`cursor://anysphere.cursor-mcp/oauth/callback` and `\http://localhost:8787/callback`

|OpenCode
|`\http://127.0.0.1:19876/callback` and `\http://localhost:19876/callback`
|===
. Optional: If users also sign in from Cursor on the web or from Cursor Agents, select *Add a platform* > *Web*, and add `\https://www.cursor.com/agents/mcp/oauth/callback`.
. On the *Settings* tab, set *Allow public client flows* to *Yes*, and save.
. Under *API permissions*, add the Microsoft Graph delegated permission `offline_access` so that the client can refresh tokens without asking the user to sign in again.
. If your tenant requires admin consent, select *Grant admin consent*.

If sign-in fails with error `AADSTS50011`, the callback URI of the AI client isn't registered. The error shows the exact URI to add. Add it under *Mobile and desktop applications*, and use the same port in the client configuration that you register here.

[#set-up-an-identity-provider]
== Set up an identity provider

Connect Microsoft Entra ID as an identity provider (IdP) to authenticate and authorize access to the data resources in your data collections.

.Before you begin

* You must have the _AI Data Engine administrator_ role.
* You have the tenant ID and the application (client) ID of the AI Data Engine application that you registered in Microsoft Entra ID.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine*.
. Select *Configuration* > *Identity providers*.
. Select *Add identity provider*.
+
The *Add identity provider* panel opens.
. From *Select identity provider*, select *Microsoft EntraID*.
. In *Entra Tenant ID*, enter the Directory (tenant) ID of your Entra ID tenant.
. In *Application (Client) ID*, enter the Application (client) ID of the AI Data Engine application.
+
IMPORTANT: Enter the Application (client) ID, which is a GUID. Don't enter the Application ID URI. Tokens identify the AI Data Engine application by its GUID, so a URI causes sign-in failures.
+
Use the identifiers from your Microsoft Entra ID configuration. AI Data Engine checks the format of both values and confirms that the tenant exists. If an *Invalid identity* message appears, verify the values and correct them before you try again.
. Select *Add identity provider*.

When setup completes, AI Data Engine displays the confirmation message *Identity provider successfully created.* The provider appears in the *Identity providers* list. Before you continue, confirm that its *Connection status* is *Connected*.

Use the same Application (client) ID as the client ID in your AI clients.

Changes to identity provider and collection settings might not take effect immediately because NetApp Console applies them to the MCP server asynchronously.

Adding an identity provider doesn't automatically associate it with a data collection. Select the identity provider when you configure the collection so that AI applications can access its resources with authentication and authorization. Refer to <<configure-collections-for-mcp,Configure collections for MCP>>. You can delete an identity provider only if no collection uses it. To edit one, refer to link:maintain-mcp-setup.html#update-an-identity-provider[Update an identity provider].

After you set up an identity provider and create a collection, configure the collection for MCP in NetApp Console. [#token-expectations]
== Token expectations

AI clients must send an Entra ID access token in the `Authorization: Bearer` header of each request. AI Data Engine validates the token on every request. It accepts a token only if all of these are true:

* The signature is valid, and the token is a v2.0 token issued by your Entra ID tenant (issuer).
* Its audience (`aud`) matches the Application (client) ID of the AI Data Engine application.
* It hasn't expired. Entra ID access tokens typically last about one hour. Clients that request `offline_access` can refresh tokens without asking the user to sign in again.

A token for a power-user session carries the `power_users` scope in its `scp` claim and the `AIDEPowerUsers` app role in its `roles` claim.

If a token is missing, expired, or invalid, AI Data Engine returns `401 Unauthorized`. A `401` response after sign-in usually means that Entra ID issued a v1 token, or that the tenant ID or Application (client) ID in AI Data Engine doesn't match your Entra ID application. Confirm that `requestedAccessTokenVersion` is set to `2` and recheck the identity provider values in NetApp Console.

If AI Data Engine can't verify a user's identity or scope, it returns no data from the collection.

You don't need to configure optional claims in Entra ID for AI Data Engine to accept a token.

[#verify-your-configuration]
== Verify your configuration

Before users connect, confirm that each of the following is true. The Application ID URI, scope, tenant ID, and client ID must match exactly in Entra ID, NetApp Console, and your AI clients.

*MCP host*

* The MCP host name is on a domain that is verified in Entra ID.
* The host name resolves from user machines.
* The host presents a certificate that client machines trust.
* `\https://<host>/mcp/tools` returns `401` when you send no token.

*Microsoft Entra ID*

* A dedicated application is registered.
* The Application ID URI is `\https://<host>/mcp/tools`.
* The `power_users` scope exists, and `requestedAccessTokenVersion` is set to `2` in the manifest.
* A redirect URI is registered for each AI client, and public client flows are allowed.
* The `AIDEPowerUsers` app role is assigned to your users.

*NetApp Console*

* The Entra ID identity provider has the tenant ID and the application (client) ID, and its connection status is *Connected*.
* The collection is configured for MCP with the identity provider and the `power_users` scope.
* You generated the MCP code snippet.

*AI client*

* The snippet is added to the AI client.
* The client ID is the application (client) ID.
* The scope is the Application ID URI plus `/power_users`.
* After you sign in once, the AI Data Engine tools are listed.
