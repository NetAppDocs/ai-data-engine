= Quick start for governed AI access with AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
Set up governed AI access with AI Data Engine by preparing Microsoft Entra ID, configuring a data collection for MCP, and connecting an AI client that can search the collection and tag files through the Model Context Protocol (MCP).

This quick start assumes that you have already link:../data-sources/connect-data-source.html[connected a data source] and that AI Data Engine has scanned and indexed it. You also need permission to register applications and grant consent in Microsoft Entra ID, and the MCP server must have a host name that your AI clients can reach over HTTPS.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png[One] link:configure-mcp-access.html[Prepare Microsoft Entra ID]
[role="quick-margin-para"]
In the Microsoft Entra admin center, link:configure-mcp-access.html#register-the-ai-data-engine-application[register an application for AI Data Engine], and then link:configure-mcp-access.html#define-scopes-and-the-power-user-app-role[add the power_users scope]. Create the `AIDEPowerUsers` app role and assign it to the users or groups who tag files in collections, such as storage administrators. Tagging requires both the app role and the `power_users` scope. Record the tenant ID and the application (client) ID.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png[Two] link:configure-mcp-access.html#set-up-an-identity-provider[Connect Entra ID to AI Data Engine]
[role="quick-margin-para"]
In NetApp Console, set up Microsoft Entra ID as an identity provider by entering the tenant ID and the application (client) ID.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png[Three] link:manage-data-collections.html#create-a-data-collection[Create a data collection]
[role="quick-margin-para"]
Create a data collection to define the data resources that AI clients can search through the MCP server. The new collection has a status of `Ready to configure`.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png[Four] link:manage-data-collections.html#configure-a-collection-for-mcp[Configure the collection for MCP]
[role="quick-margin-para"]
Configure the collection for MCP by selecting the identity providers and user scopes that can access it. Then generate the MCP code snippet, and copy the MCP server URL or a client-specific configuration snippet.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png[Five] link:connect-ai-clients-mcp.html[Connect an AI client]
[role="quick-margin-para"]
Use the MCP server URL or the client-specific configuration snippet that you copied in the previous step. It includes the MCP server URL, the Entra ID tenant ID, the client application ID, the scopes, and the collection ID. If your AI client needs its own Entra ID application, register it, create a client secret, and add the application ID and the secret to the configuration. Then add the configuration to a supported AI client, such as Claude Desktop, Cursor, or Visual Studio Code with GitHub Copilot. The configuration must request the `power_users` and `offline_access` scopes.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png[Six] link:connect-ai-clients-mcp.html[Sign in and verify the connection]
[role="quick-margin-para"]
Sign in with Microsoft Entra ID when the AI client prompts you, and accept the consent prompt if it appears. Confirm that the AI Data Engine tools are listed in your AI client, and then link:connect-ai-clients-mcp.html#sample-prompts[try sample prompts], such as asking for the collections that you can search or listing the tags in a collection.
