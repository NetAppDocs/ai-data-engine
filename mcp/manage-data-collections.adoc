== How collections define MCP scope

A data collection is a group of files from volumes that you select in AI Data Engine. When you enable a collection for AI access, AI clients can search the metadata for the files in that collection. AI clients can't search files outside the collections that you enable. To create a collection, refer to <<create-a-data-collection,Create a data collection>>.

To change a collection, an identity provider, or the MCP server settings later, refer to link:maintain-mcp-setup.html[Maintain your MCP setup].

You grant access to a collection by assigning it one or more Microsoft Entra ID scopes. Access is granted at the collection level only. In a power-user session, search isn't filtered by file-level permissions, so the session can search every file in the collection.

CAUTION: Before you grant a scope access to a collection, confirm that everyone who has that scope is allowed to search the metadata for every file in the collection.

[#create-a-data-collection]
== Create a data collection

Create a data collection to define the data resources that AI clients can search through the MCP server.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine*.
. Select *Configuration*, then select *MCP collections*.
. Select *Create collection*.
. In *Name*, enter a unique name for the collection.
. Optional: In *Description*, enter a description to help your team understand the collection's purpose. The description can contain up to 512 characters.
. Use the *Systems* and *Protocols* filters to narrow the list of data resources.
. Select the checkbox next to each data resource that you want to include in the collection.
+
The *Selected rows* summary displays the number of selected resources, their scanned capacity, and their scanned file count. To clear the selection and start again, select *Reset*.
. Select *Create MCP collection*.

A confirmation message appears, and the new collection is added to the *Collections* list with a status of *Ready to configure*. Creating the collection doesn't complete its MCP connection configuration.

[#configure-a-collection-for-mcp]
== Configure a collection for MCP

Select the identity providers and user scopes for an MCP collection, and then obtain the connection details for your AI client.

.Before you begin

* You have created an MCP collection. Refer to <<create-a-data-collection,Create a data collection>>.
* The identity providers that you want to use are connected to AI Data Engine. Refer to link:configure-mcp-access.html#set-up-an-identity-provider[Set up an identity provider].

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine* > *Configuration* > *MCP collections*.
. Locate the collection that you want to configure, open its *Actions* menu, and select *Configure for MCP*.
. In the *Select identity providers* step, select one or more identity providers to authenticate and authorize access to the collection.
+
NOTE: If the identity provider that you need isn't listed, add it under *Identity providers* before you continue. If administrator access is required, ask your administrator to connect the identity provider.
. For each selected identity provider, use *User scopes to include* to specify the scopes:
.. To include all user scopes, leave *All user scopes* selected.
.. To include specific scopes, open the dropdown, select the scopes, and select *Add scopes*.
+
`power_users` is the only scope in the dropdown, and selecting it gives the same result as *All user scopes*.
. Select *Generate MCP code snippet*.
. In the *Generate MCP code snippet* step, copy the connection details that your AI client requires:
* To use the endpoint directly, select the copy icon next to *MCP server URL*.
* To use a client-specific configuration snippet, select the *Claude* or *Cursor* tab under *Code snippets*, and then select the copy icon.
+
NOTE: If the *MCP hostname not setup* warning appears, select *MCP settings* to configure the hostname. Securing the MCP server with HTTPS requires an SSL/TLS certificate.
. Optional: To change the identity providers or user scopes, select *Go back*, and then generate the snippet again.
. Select *Close*.

.Result

You have the MCP server URL or a client-specific configuration snippet for the selected identity providers and user scopes. Use these details to connect your AI client and validate access to the collection. If your AI client needs its own Entra ID application, register it and add its client application ID and client secret to the snippet. Refer to link:configure-mcp-access.html#register-an-application-for-each-ai-client[Register an application for each AI client].

NOTE: Generating connection details doesn't connect or validate your AI client. Complete those tasks in the AI client.

Users whose tokens carry a granted scope can discover and search the collection. Users without a matching scope can't discover, search, or work with the collection.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine*.

== Disable AI access for a collection

Disable AI access for a collection when AI clients no longer need to search it.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine*.
. Select the collection that you want to disable.
. Turn off AI access for the collection.
. Save your changes.
