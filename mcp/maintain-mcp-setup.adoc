= Maintain your AI Data Engine MCP setup
:icons: font
:imagesdir: ../media/

[.lead]
Review and update your MCP collections, identity providers, access scopes, and server settings as your requirements change.

== Before you begin

* You have configured an MCP collection and connected an AI client. Refer to link:quick-start-mcp.html[Quick start for governed AI access with AI Data Engine].
* You have the permissions that are required to change the settings that you want to update.

[#review-mcp-server-and-collection-status]
== Review MCP server and collection status

Review the status of the MCP server and of the collections that your AI clients use, and address any configuration warnings.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine* > *Configuration* > *MCP collections*.
. Review the MCP server status and the status of the collections that your AI clients use.
. Address any configuration warnings.

[#edit-a-data-collection]
== Edit a data collection

Update the name, description, or data resources of an MCP collection.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine* > *Configuration* > *MCP collections*.
. Open the collection's *Actions* menu and select *Edit*.
. Update the name or description as needed.
. Select or clear data resources to update the collection.
. Select *Save MCP collection*.

[#update-an-identity-provider]
== Update an identity provider

Update an identity provider when its Microsoft Entra ID configuration changes.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine* > *Configuration* > *Identity providers*.
. Open the identity provider for editing.
. Update the tenant ID, application (client) ID, or name as needed.
. Select *Save*.

If administrator access is required, ask your administrator to update the identity provider.

[#update-identity-providers-or-user-scopes-for-a-collection]
== Update the identity providers or user scopes for a collection

Change which identity providers authorize access to a collection, or which user scopes they include, and then copy the updated connection details.

.Before you begin

If the identity provider that you need isn't listed, connect it under *Identity providers* first. Refer to link:configure-mcp-access.html#set-up-an-identity-provider[Set up an identity provider].

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine* > *Configuration* > *MCP collections*.
. Open the collection's *Actions* menu and select *Configure for MCP*.
. Select the identity providers that authorize access to the collection.
. For each selected identity provider, review *User scopes to include*. Keep *All user scopes*, or select specific scopes and select *Add scopes*.
. Select *Generate MCP code snippet*.
. Copy the updated *MCP server URL* or the configuration snippet for your AI client, and then select *Close*.

.Result

The collection uses the identity providers and user scopes that you selected. If the MCP server URL or the configuration snippet changed, update each affected AI client. Refer to <<update-ai-client-connections-and-validate-access,Update AI client connections and validate access>>.

For more information about this task, refer to link:manage-data-collections.html#configure-a-collection-for-mcp[Configure a collection for MCP].

[#review-mcp-server-settings]
== Review MCP server settings

Review whether AI clients can connect to the MCP server, and review the MCP host name.

.Steps

. In NetApp Console, go to *AI data hub* > *AI Data Engine* > *Configuration* > *MCP collections*.
. Select *MCP settings*.
. Under *MCP server connection*, review *Enable connection to MCP*.
+
CAUTION: Disabling the MCP server connection blocks all requests from AI clients to all MCP collections. Disable the connection only when you intend to suspend access across the server.
. Under *MCP host name*, review the host name. If you need to change it, enter the updated host name and select *Configure*.
+
NOTE: Securing the MCP server with HTTPS requires an SSL/TLS certificate.
. Select *Close*.

[#update-ai-client-connections-and-validate-access]
== Update AI client connections and validate access

After you change collections, identity providers, user scopes, or server settings, confirm that your AI clients can still connect and that access matches your intended permissions.

.Steps

. If the MCP server URL or the generated configuration snippet changed, update the connection settings in each affected AI client. Refer to link:connect-ai-clients-mcp.html[Connect AI clients].
. In each affected AI client, confirm that the client can connect and authenticate.
. Run a representative search request.
. Confirm that the expected collection content is accessible and that access matches the intended permissions.

.Result

Your MCP setup reflects your changes, and you confirmed that your affected AI clients can connect and that access matches your intended permissions.
