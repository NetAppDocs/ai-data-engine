= Manage data sources in AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
Keep scan coverage aligned with the data you need to analyze. Use the *Data sources* page to check scan progress, investigate gaps in coverage, and manage which systems and data resources AI Data Engine scans.

[[view-scan-status-and-details]]
== View scan status and details

Check scan status to see how scanning is progressing and to identify resources that need attention. Review system-level progress and resource-level details to distinguish scans that are still running from those that are paused or have errors.

If scans stop or pause unexpectedly, check deployment health. Refer to link:../administer/monitor-deployment-health.html[Monitor deployment health and investigate issues].

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system you want to review.
. Select the system row and open the detail view.
+
The detail view shows:
+
* A status overview with current scan progress
* A breakdown of data resource scan states: running, completed, paused, and errors
* Scan permission mode (for example, "Scan without write permissions")
+
If scan errors appear, expand the error details to see which data resources (volumes, shares, buckets, or schemas) are affected and the reason for the failure.

== Pause scanning

Temporarily stop scanning a system when you don't want AI Data Engine to scan it for a period of time. The system stays connected, and you can resume scanning later.

// RESEARCH: Confirm the supported pause use cases and how Pause differs from Deactivate AI Data Engine (for example, whether queued or in-progress scans are affected).

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system you want to pause.
. Select the system row to open the detail view.
. Select *Pause*.

== Resume scanning

Resume scanning when you're ready for AI Data Engine to scan a paused system again.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the paused system.
. Select the system row to open the detail view.
. Select *Resume*.

== Scan all data resources

Refresh metadata across a system after significant data changes so that your analysis reflects the updated data. Use this action to request an immediate scan of all data resources on the system.
// RESEARCH: Confirm whether "Scan all volumes" and "Activate scans" share the same underlying action; confirm the exact kebab menu label in the V2 UI.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system you want to scan.
. Select the actions menu next to the system.
. Select *Scan all volumes* (there is an equivalent option in the actions menu for shares and buckets).

== Retry failed scans

Restore scan coverage for resources that could not be scanned successfully. First resolve the cause of the failure, such as a credential issue, network error, or permission problem, and then retry the failed scans.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system with failed scans.
. Select the actions menu next to the system.
. Select *Retry all scans*.

== Edit CIFS credentials

Maintain or restore access to SMB shares when the scan account's credentials change or authentication fails. Update the SMB (CIFS) credentials that AI Data Engine uses to authenticate to the shares.

NOTE: If the share uses Kerberos authentication, AI Data Engine authenticates with a ticket from the keytab, and no password is stored in the data source. Refer to link:../administer/configure-kerberos-smb.html[Kerberos authentication for SMB/CIFS shares in AI Data Engine].
// RESEARCH Confirm whether Edit CIFS credentials applies to Kerberos shares and how to change the scan service account or keytab.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the SMB system.
. Select the system row to open the detail view.
. Select *Edit CIFS credentials*.
. Enter the updated username and password, then select *Save*.

== Enable or disable access to DP volumes

Include or exclude replicated data in your scan coverage by enabling or disabling access to data protection (DP) volumes. DP volumes are NetApp SnapMirror destination volumes, and AI Data Engine doesn't scan them by default. You can enable or disable access per system.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system.
. Select the system row to open the detail view.
. Select *Enable access to DP volumes* or *Disable access to DP volumes*.

== Enable or disable scanning of specific shares, buckets, or volumes

Focus scan coverage on the data resources you need to analyze without reconfiguring the entire system. Enable scanning for resources that weren't selected or available during initial setup, and disable scanning for volumes, shares, or buckets that you don't need to analyze.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system you want to update.
. Select *View details* in the system row.
. In the data resources list, locate the volume, bucket, or share you want to change.
. Use the *Scanning* toggle to enable or disable scanning for that resource.

== Deactivate AI Data Engine for a system

Remove a system from active scan coverage when you no longer need AI Data Engine to scan it. Deactivating a system stops all scanning and preserves its configuration. To include the system again, select *Activate scans* on the system row.

.Steps
. From the AI Data Engine UI, select *Data sources*.
. Locate the system you want to deactivate.
. Select the actions menu next to the system.
. Select *Deactivate AI Data Engine*.
