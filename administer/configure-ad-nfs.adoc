= Configure Active Directory identity mapping for NFS in AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
Identify the owners of your NFS files by name instead of by numeric ID. AI Data Engine can map the numeric user IDs (UIDs) and group IDs (GIDs) in NFS files to Active Directory identities, and it uses resolved user identities to display file-owner names.
// RESEARCH Does GA display owning-group names for NFS files anywhere in the UI or MCP results? If so, state where.

This mapping doesn't authenticate AI Data Engine to NFS storage. It converts the IDs that AI Data Engine finds during scanning to Active Directory names.

.Before you begin

* You have _AI Data Engine administrator_ privileges.
* You have link:../deploy/aide-requirements.html#networking-requirements[opened the required ports] from AI Data Engine to your Active Directory domain controllers.
// RESEARCH Which ports does the configured LDAP, LDAPS, or Global Catalog connection require? The requirements page lists 3268 and 3269 for the Global Catalog.
* You have an Active Directory account that AI Data Engine can use to query user and group attributes. You enter its user name and password in AI Data Engine.
// RESEARCH Confirm the permissions the Active Directory account needs and whether it must be a dedicated account.
* You have the IP address of your DNS server, the IP address and port of your LDAP server, and your Active Directory domain name.
* If AI Data Engine queries the Global Catalog and the attributes aren't yet replicated to it, you or your Active Directory administrator has the _Schema Admins_ role to make the schema change.

== Prepare Active Directory

Match the UID and GID attributes in Active Directory to the numeric IDs used on your NFS storage so AI Data Engine can resolve file owners.

AI Data Engine reads the following Active Directory attributes:

[cols="1,2,1",options="header"]
|===
|Attribute |Purpose |Required

|`uidNumber`
|The numeric UID of a user. It must match the UID that the user has on your NFS storage.
|Yes

|`gidNumber`
|The numeric GID of a group. It must match the GID that the group has on your NFS storage.
|Yes

|`mail`
|The email address of the file owner. If this attribute isn't set, the owner's email address appears as *Not Available*.
|No

|===

Populate `uidNumber` on the users and `gidNumber` on the groups that you want AI Data Engine to resolve.

NOTE: Set `gidNumber` on the group object. The `gidNumber` on a user object identifies that user's primary group. It isn't the group attribute that AI Data Engine uses for this lookup.
// RESEARCH The UI has no fields for custom UID and GID attribute names. Does AI Data Engine support custom attribute names? If so, how are they configured?

.Steps
. Verify that every user that you want to resolve has a `uidNumber` value and every group has a `gidNumber` value. Each UID must be unique among users, and each GID must be unique among groups. A user and a group can have the same numeric value.
. If AI Data Engine queries the Global Catalog and the attributes aren't already replicated to it, replicate the `uidNumber` and `gidNumber` attributes to it. This is a one-time change for the entire forest. You must be a member of the _Schema Admins_ group.
+
.. On a domain controller, open the Active Directory Schema snap-in.
.. Open the properties of the `uidNumber` attribute.
.. Select *Replicate this attribute to the Global Catalog*.
.. Repeat for the `gidNumber` attribute.
// RESEARCH Confirm the Active Directory Schema snap-in procedure for replicating attributes to the Global Catalog, or provide the supported PowerShell alternative.

CAUTION: If AI Data Engine queries the Global Catalog, attributes that aren't replicated to it aren't returned by identity lookups. The corresponding IDs remain unresolved.

== Enable Active Directory for NFS

Connect AI Data Engine to the Active Directory domain that contains the matching UID and GID attributes, then enable identity mapping so scanned NFS files can show resolved owner names.

.Steps
. From the AI Data Engine UI, select *Configuration*.
. Select *General settings*.
. Turn on the *Enabled* toggle.
. Enter the connection details for your Active Directory domain.
+
[cols="1,3",options="header"]
|===
|Field |Description

|*Username*
|The Active Directory account that AI Data Engine uses to query user and group attributes. Enter the name in the format `domain\user` or `user@domain`.

|*Password*
|The password of the account.

|*DNS Server IP address*
|The IP address of the DNS server that resolves your Active Directory domain. For example, `10.0.1.50`.

|*Domain name*
|The fully qualified name of your Active Directory domain. For example, `corp.example.com`.

|*LDAP Server IP address*
|The IP address of the LDAP server, which is a domain controller. For example, `10.0.1.50`.

|*LDAP Server Port*
|The port of the LDAP server. The default is `389`.

|*LDAP secure connection*
|Select this option to connect to the LDAP server over a secure connection.

|===

. Optionally, enable NFS identity mapping.
+
Enabling NFS identity mapping allows AIDE to resolve numeric NFS file-owner IDs to Active Directory owner names. Enable this option only if Active Directory contains the Unix UID/GID attributes used by your NFS environment. Specify the UID and GID attribute names; the defaults are `uidNumber` and `gidNumber`. Owner information is resolved in the background.
// RESEARCH Does selecting LDAP secure connection require port 636, and does the port field update automatically? Is a domain controller certificate required?
// RESEARCH Does GA support more than one Active Directory domain or forest? If so, document how to add each one. If not, state that one Active Directory is supported.
. Save your changes.

.Result

AI Data Engine uses Active Directory to resolve the owners of NFS files that it scans.

AI Data Engine resolves identities asynchronously. Owner names might not appear immediately after you enable mapping or update attributes in Active Directory.

To check the result, open the file details in the link:../investigate/investigate-unstructured.html[Investigation] view and verify that the file owner shows an Active Directory user name.
