= Map NFS users and groups to Active Directory in AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
NFS files identify their owners and groups by numeric user IDs (UIDs) and group IDs (GIDs). To show owner and group names for NFS data, AI Data Engine looks up those IDs in Active Directory. Complete the Active Directory prerequisites, and then enable Active Directory for NFS in AI Data Engine settings.

This mapping doesn't authenticate AI Data Engine to NFS storage. It converts the IDs that AI Data Engine finds during scanning to Active Directory user and group names.

.Before you begin

* You have _AI Data Engine administrator_ privileges.
* You have link:../deploy/aide-requirements.html#kerberos-ad-requirements[opened the required ports] from AI Data Engine to your Active Directory domain controllers, including the Global Catalog ports (3268 and 3269).
* You have an Active Directory account that AI Data Engine can use to query user and group attributes. You enter its user name and password in AI Data Engine.

* You have the IP address of your DNS server, the IP address and port of your LDAP server, and your Active Directory domain name.
* You have access to Active Directory with the _Schema Admins_ role if the attributes aren't yet replicated to the Global Catalog.

== Prepare Active Directory

AI Data Engine reads the following Active Directory attributes:

[cols="1,2,1",options="header"]
|===
|Attribute |Purpose |Required

|`uidNumber`
|The numeric UID of a user. It must match the UID that the user has on your NFS storage.
|Yes

|`gidNumber`
|The numeric GID of a group. It must match the GID that the group has on your NFS storage.
|Yes

|`mail`
|The email address of the file owner. If this attribute isn't set, the owner's email address appears as *Not Available*.
|No

|===

AI Data Engine looks up the `uidNumber` and `gidNumber` attributes by their default names.
// RESEARCH The UI has no fields for custom UID and GID attribute names. Does AI Data Engine support custom attribute names? If so, how are they configured?

.Steps
. Verify that every user and group you want to resolve has a `uidNumber` or `gidNumber` value. Each value must be unique across the domain.
. Replicate the `uidNumber` and `gidNumber` attributes to the Global Catalog. This is a one-time change for the entire forest. You must be a member of the _Schema Admins_ group.
+
.. On a domain controller, open the Active Directory Schema snap-in.
.. Open the properties of the `uidNumber` attribute.
.. Select *Replicate this attribute to the Global Catalog*.
.. Repeat for the `gidNumber` attribute.

CAUTION: If these attributes aren't replicated to the Global Catalog, AI Data Engine can't resolve IDs to names. Owners and groups remain unresolved.

== Enable Active Directory for NFS

.Steps
. From the AI Data Engine UI, select *Configuration*.
. Select *General settings*.
. Turn on the *Enabled* toggle.
. Enter the connection details for your Active Directory domain.
+
[cols="1,3",options="header"]
|===
|Field |Description

|*Username*
|The Active Directory account that AI Data Engine uses to query user and group attributes. Enter the name in the format `domain\user` or `user@domain`.

|*Password*
|The password of the account.

|*DNS Server IP address*
|The IP address of the DNS server that resolves your Active Directory domain. For example, `10.0.1.50`.

|*Domain name*
|The fully qualified name of your Active Directory domain. For example, `corp.example.com`.

|*LDAP Server IP address*
|The IP address of the LDAP server, which is a domain controller. For example, `10.0.1.50`.

|*LDAP Server Port*
|The port of the LDAP server. The default is `389`.

|*LDAP secure connection*
|Select this option to connect to the LDAP server over a secure connection.

|===

. Save your changes.

.Result

AI Data Engine uses Active Directory to resolve the owners and groups of NFS files that it scans.

If an ID doesn't resolve, AI Data Engine retries the lookup after 24 hours. If you correct the attributes in Active Directory after a scan, owner and group names can take up to 24 hours to appear.
