= AI Data Engine architecture
:icons: font
:imagesdir: ../media/

[.lead]
AI Data Engine consists of a metadata catalog, a connectivity agent, and a policy engine. These components work together to extract metadata from your storage systems, catalog it, and execute policies against it.

=== Metadata Engine

The Metadata Engine is the core catalog of AI Data Engine. It scans connected storage systems to extract file system metadata and stores that metadata in a searchable index. The catalog is updated continuously as files change on your storage systems.

=== Console Agent

The Console Agent runs on a customer-managed host and maintains the connection between AI Data Engine and NetApp Console. It handles authentication, connectivity verification, and communication with the Metadata Engine.

=== Policy Engine

The Policy Engine evaluates saved policies against the metadata catalog. When a policy's criteria are matched, the Policy Engine triggers the configured action, such as tagging, archiving, or deleting files.

== Deployment models

AI Data Engine supports two deployment models:

AIDE Lite:: A single-VM deployment suitable for smaller environments. Available in Small, Medium, and Large configurations. AIDE Lite is the recommended starting point for most deployments.

AIDE Enterprise:: A Kubernetes-based deployment for larger environments requiring scalability and high availability. Available in Medium and Large configurations.

== Data flow

. AI Data Engine deploys in your on-premises environment.
. You connect one or more storage systems as data sources.
. The Metadata Engine scans the clusters via NFS and CIFS/SMB protocols to extract file metadata.
. Metadata is indexed in the catalog.
. The dashboard surfaces storage insights from the catalog.
. Investigation lets you query the catalog directly with metadata filters.
. Policies evaluate the catalog on an ongoing basis and trigger configured actions.
