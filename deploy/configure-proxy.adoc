= Configure a proxy for AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
If your AI Data Engine host or cluster cannot reach the internet directly, configure a forward proxy so the installer can download components, pull container images, and communicate with NetApp Console. Traffic to local infrastructure — the Console Agent, the Kubernetes API, ONTAP, and NFS/SMB storage — always bypasses the proxy and connects directly. The same proxy options work for both `install-lite.sh` and `install-enterprise.sh`.

== Supported proxy configurations

[cols="2,3,2",options="header"]
|===
|Configuration |Description |Authentication

|No proxy
|Direct connection to the internet; no proxy is used.
|None

|Unauthenticated forward proxy
|Forward proxy that does not require credentials.
|None

|Authenticated forward proxy
|Forward proxy that requires credentials.
|HTTP Basic authentication (username and password)

|===

IMPORTANT: AI Data Engine supports standard forward proxies that tunnel connections with HTTP `CONNECT`, including HTTPS destinations. Proxies that decrypt and re-sign HTTPS traffic with a custom certificate authority (TLS-inspecting proxies) are not supported.

----

== Proxy configuration parameters

[cols="2,1,3",options="header"]
|===
|Parameter |Default |Description

|`--proxy-host <host[:port]>`
|None
|Hostname or IP address of the forward proxy. Enables proxy configuration. Accepts an inline port (`host:port`) instead of using `--proxy-port`.

|`--proxy-port <port>`
|`80` for HTTP, `443` for HTTPS
|Port the proxy listens on. Ignored if the port is already included in `--proxy-host`.

|`--proxy-scheme <http\|https>`
|`http`
|Protocol used to connect to the proxy server itself.

|`--proxy-user <user>`
|None
|Username for basic authentication. Requires a password, supplied with `--proxy-password-file` or entered interactively.

|`--proxy-password-file <path>`
|None
|Path to a local file, with permissions set to `0600`, containing the proxy password.

|`--proxy-bypass <hosts>`
|None
|Comma-separated hostnames, IP addresses, or CIDR blocks that bypass the proxy in addition to local infrastructure traffic.

|`--no-proxy`
|—
|Explicitly disables proxy configuration and skips proxy prompts.

|===

NOTE: `--proxy-password` is not supported as a command-line argument, to avoid exposing credentials in process tables, shell history, or logs. Use `--proxy-password-file` or the interactive prompt instead.

== Configure the proxy

Choose one of the following methods to configure the proxy when you run the install command copied from NetApp Console.

=== Configure the proxy using command-line flags

Replace `--no-proxy` in the copied install command with your proxy parameters:

[source,bash]
----
sudo ./install-lite.sh \
  --proxy-host proxy.customer.example \
  --proxy-port 8080 \
  --proxy-scheme http \
  --proxy-user aide-proxy-user \
  --proxy-password-file /root/aide-proxy.pass \
  --proxy-bypass connector.customer.example,10.0.0.0/8
----

If your proxy doesn't require authentication, omit `--proxy-user` and `--proxy-password-file`. If you omit `--proxy-password-file`, the installer prompts you to enter the password interactively.

NOTE: Use `install-enterprise.sh` in place of `install-lite.sh` for AIDE Enterprise deployments; the same proxy flags apply to both installers.

=== Configure the proxy using interactive guided setup

. Remove `--no-proxy` from the copied install command and run it without any proxy flags.
. When prompted `Do you want to configure a proxy? [y/N]`, enter `y`.
. Follow the interactive prompts to enter the proxy host, port, scheme, username, and password.
