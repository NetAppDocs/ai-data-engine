= Learn about proxies for AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
If your AI Data Engine host or cluster cannot reach the internet directly, configure a forward proxy so the installer and AI Data Engine can download components, pull container images, and register with NetApp Console. The proxy options are the same for single-node and multi-node deployments. The steps to prepare for and run the installation differ, so each deployment type has its own workflow.

== Deploy AI Data Engine with a proxy

Each deployment type has its own topic with the complete procedure, from preparing the environment to running the installer and troubleshooting.

* link:deploy-aide-single-node-proxy.html[Deploy AI Data Engine as a single-node deployment with a proxy]: The installer configures the proxy for the host, the k3s runtime, and the host trust store.
* link:deploy-aide-multi-node-proxy.html[Deploy AI Data Engine as a multi-node deployment with a proxy]: You configure the container runtime proxy and the CA certificate trust on every node before you run the installer.

== What goes through the proxy

Only internet-bound traffic uses the proxy. All AI Data Engine internet destinations use HTTPS on port 443, so your proxy must allow `CONNECT` to port 443 for each endpoint and host in <<proxy-allowlist,Hosts to allow on your proxy>>.

Traffic on your network connects directly and must stay reachable without the proxy:

* The Console agent (`--cm-host`)
* NFS, CIFS/SMB, ONTAP, and StorageGRID data sources
* Active Directory and LDAP
* The Kubernetes API server and the cluster's internal networks

== Supported proxy configurations

[cols="2,3,2",options="header"]
|===
|Configuration |Description |Authentication

|No proxy
|Direct connection to the internet; no proxy is used.
|None

|HTTP forward proxy
|AI Data Engine connects to the proxy over HTTP and tunnels HTTPS destinations with `CONNECT`.
|None, or HTTP Basic authentication (username and password)

|HTTPS forward proxy
|AI Data Engine connects to the proxy over TLS. If a private certificate authority (CA) signed the proxy certificate, you supply the CA certificate.
|None, or HTTP Basic authentication (username and password)

|===

You can address the proxy by hostname or IPv4 address.

IMPORTANT: AI Data Engine supports standard forward proxies that tunnel connections with HTTP `CONNECT`, including HTTPS destinations. Proxies that decrypt and re-sign HTTPS traffic with a custom certificate authority (TLS-inspecting proxies) are not supported. If your proxy inspects TLS traffic, exempt the endpoints and hosts in <<proxy-allowlist,Hosts to allow on your proxy>> from inspection, including the installer download host.

// RESEARCH Update the TLS-inspecting proxy wording and the proxy type prompt guidance if QA qualifies TLS inspection for GA and the product manager approves it.
The following proxy features are not supported:

* NTLM, Kerberos, or client-certificate authentication to the proxy
* SOCKS proxies
* Proxy auto-configuration (PAC file or WPAD). Give the installer the proxy host and port directly.
* A different proxy for different destinations. One proxy carries all AI Data Engine internet traffic.
* An IPv6 address as the proxy address. Use a hostname instead; the hostname can resolve to IPv6.
* A proxy with an air-gapped installation. The installer rejects proxy options on an air-gapped installation.

The installer uses one proxy for every internet destination and every AI Data Engine component. The proxy settings are set during installation.

[[proxy-parameters]]
== Proxy configuration parameters

[cols="2,1,3",options="header"]
|===
|Parameter |Default |Description

|`--proxy-host <host[:port]>`
|None
|Hostname or IPv4 address of the forward proxy, without `http://` or `https://`. Enables proxy configuration. Accepts an inline port (`host:port`). A port in `--proxy-host` takes precedence over `--proxy-port`.

|`--proxy-port <port>`
|`80` for HTTP, `443` for HTTPS
|Port the proxy listens on. Ignored if the port is already included in `--proxy-host`.

|`--proxy-scheme <http\|https>`
|`https`
|Protocol used to connect to the proxy server itself. This is not the scheme of the destinations that the proxy reaches. Most forward proxies listen on plain HTTP, so pass `--proxy-scheme http` for those.

|`--proxy-ca-cert <path>`
|None
|Path to a PEM file, or to a flat directory of `.crt` and `.pem` files, that contains the CA certificate that signed the proxy certificate. The installer reads a directory without recursing into subdirectories and merges the files into one bundle. Required for an HTTPS proxy whose certificate is signed by a private CA. Not used with an HTTP proxy.

|`--proxy-user <user>`
|None
|Username for basic authentication. With an HTTP proxy, the installer warns that credentials travel to the proxy unencrypted. Requires a password, supplied with `--proxy-password-file` or entered at the prompt.

|`--proxy-password-file <path>`
|None
|Path to a local file that contains only the proxy password, with permissions set to `0600` or `0400`. If you omit it, the installer prompts for the password with hidden input.

|`--proxy-type <r>`
|`r`
|Type of proxy. `r` is a regular forward proxy and is the default. Don't change it. TLS-inspecting proxies are not supported.

|`--proxy-bypass-registries <list>`
|None
|Single-node deployments only. Comma-separated list of container registries that the host reaches directly instead of through the proxy, for example an internal registry mirror. Accepts a host, `.domain`, `host:port`, IPv4 address, or CIDR. AWS hosts are rejected because AI Data Engine images must come from the NetApp container registry through the proxy.

|`--no-proxy`
|—
|Explicitly disables proxy configuration and skips proxy prompts. Use it only when the host has direct internet access.

|===

NOTE: The installer doesn't accept `--proxy-password` or the `PROXY_PASSWORD` environment variable. Use `--proxy-password-file` or the interactive prompt instead.

== Supply the proxy settings

You can supply the proxy settings in two ways when you run the install command copied from NetApp Console:

* *Interactive guided setup*: Run the install command in a terminal without proxy flags. The installer prompts you for the proxy settings. This is the default method.
* *Command-line flags*: Add the proxy flags to the install command. Use this method for automated or other non-interactive deployments that must run without prompts. The flags are optional. The installer prompts you for any proxy information you don't supply.

[[interactive-prompts]]
=== Interactive guided setup

When the installer runs in a terminal and you pass neither `--proxy-host` nor `--no-proxy`, it asks the following questions. If you pass a value as a parameter, the installer doesn't ask for it again.

// RESEARCH Confirm the prompt wording at release, including the proxy type prompt, and update the proxy type guidance if TLS inspection is qualified for GA.
[cols="2,3",options="header"]
|===
|Prompt |What to enter

|`Configure outbound proxy? (y/N)`
|Enter `y` if the host reaches the internet only through a proxy. The default is no.

|Proxy host or IP
|Enter the proxy hostname or IPv4 address, optionally with a port (`host:port`).

|Proxy scheme (`https` or `http`)
|Enter the protocol that your proxy listens on. The default is `https`.

|Proxy port
|Enter the proxy port. The default is `443` for HTTPS and `80` for HTTP.

|Proxy type
|Press Enter to accept the default, a regular forward proxy.

|CA certificate for the proxy's own certificate (HTTPS only, optional)
|Enter the path to the CA file or directory. Press Enter if a public CA signed the proxy certificate.

|Does the proxy require a username and password? (y/N)
|If yes, enter the username, and then enter the password twice. The installer doesn't echo the password.
|===

=== Command-line flags

Add the proxy flags after the last existing parameter in the install command. If you run the command as copied, add them inside the quotes, before the closing quote. If the copied install command includes `--no-proxy`, remove it when you add `--proxy-host`.

* If your proxy doesn't require authentication, omit `--proxy-user` and `--proxy-password-file`.
* If the proxy certificate is signed by a publicly trusted CA, or you use an HTTP proxy, omit `--proxy-ca-cert`.
* If you specify `--proxy-user` without `--proxy-password-file`, the installer prompts you for the password when you run it from a terminal.
* Without a terminal, the installer never prompts. Pass `--proxy-host` to use a proxy, and `--proxy-password-file` if the proxy needs a password. In a non-interactive run that is missing required proxy information, the installer stops before it makes any network connection.

CAUTION: With an HTTP proxy, the proxy username and password are sent in clear text. Use an HTTPS proxy when the proxy requires authentication.

== The installer download

The install command copied from NetApp Console downloads the installer from a content delivery network (CDN) and then runs it in one step. The download doesn't use the proxy. If the target host reaches the internet only through a proxy, you download the installer yourself and run the install command from the extracted installer. The deployment topics describe these steps.

[[proxy-verification]]
== Proxy verification

Before the installer downloads anything, it runs a check from the installer host. The check confirms that the proxy responds, that the proxy accepts your credentials, and that the proxy certificate is valid for the scheme you chose. If the check fails, the installer stops and names the cause, for example a wrong port, a wrong scheme, or a rejected password (HTTP 407).

For multi-node deployments, the check covers the proxy only. It does not test whether the cluster nodes can reach the proxy.

== Change proxy settings after installation

The proxy settings are set during installation. The installer doesn't run again on an installed cluster. To change the proxy host, port, credentials, or CA certificate after installation, contact NetApp Support.
