== Networking requirements

The following network connections must be open:

[cols="2,1,1,1,2",options="header"]
|===
|Connection |Port |Protocol |Direction |Purpose

|Console Agent to NetApp Console
|443
|TCP
|Outbound
|HTTPS: connectivity to NetApp Console

|Console Agent to ONTAP
|443
|TCP
|Outbound
|HTTPS: ONTAP cluster discovery

|Console Agent to AI Data Engine
|80, 443, 8080, 9000
|TCP
|Bidirectional
|Communication between Console Agent and AI Data Engine

|AI Data Engine to ONTAP (NFS)
|111, 2049
|TCP/UDP
|To storage
|NFS data source access

|AI Data Engine to ONTAP (CIFS/SMB)
|139, 445
|TCP/UDP
|To storage
|CIFS/SMB data source access

|AI Data Engine to Active Directory
|389, 636, 3268, 3269
|TCP/UDP
|Outbound
|LDAP (389), LDAPS (636), and Global Catalog (3268, 3269) for user authentication and CIFS/SMB scanning. Port 389 uses both TCP and UDP; all other ports use TCP only.

|===

=== Additional prerequisites

* Root or sudo access on the target VM to run the installer
* 1 GbE minimum network connection
* bash 4.0 or later, curl, and tar available on the target host

== AIDE Enterprise requirements

* RKE2 v1.34 or later (v1.36.x recommended)
* Helm 3.12 or later installed on the machine from which you run the installer
* A configured StorageClass available on the cluster
* An NFS server with at least one exported path for the AIDE configuration data volume
* kubectl access with cluster-admin privileges on the machine from which you run the installer

== Dark site requirements

Dark site deployments do not require outbound internet access from the AI Data Engine host. NetApp provides all container images, Helm charts, and installation scripts as a single offline bundle that you transfer into your air-gapped environment.

The following connections must be open within the air-gapped environment. The outbound internet endpoints listed in the <<Outbound internet access>> table do not apply.

|AI Data Engine host or cluster to Console Connector
|80
|TCP
|Outbound
|HTTP: communication with the on-prem Console Connector on the local network. The installer and operator communicate with the Connector at `\http://<connector-ip>`.

|Console Agent to AI Data Engine
|80, 443, 8080, 9000
|TCP
|Bidirectional
|Communication between Console Agent and AI Data Engine

|AI Data Engine to ONTAP (NFS)
|111, 2049
|TCP/UDP
|To storage
|NFS data source access

|AI Data Engine to ONTAP (CIFS/SMB)
|139, 445
|TCP/UDP
|To storage
|CIFS/SMB data source access

|AI Data Engine to Active Directory
|389, 636, 3268, 3269
|TCP/UDP
|Outbound
|LDAP (389), LDAPS (636), and Global Catalog (3268, 3269) for user authentication and CIFS/SMB scanning

|Cluster nodes to NFS server (Enterprise only)
|111, 2049
|TCP/UDP
|To NFS server
|Access to the charts NFS share (read-only) and the AIDE data NFS share (writable). Both shares must be reachable from all cluster nodes.

|===

[#dark-site-nfs-requirements]
=== NFS share requirements (Enterprise dark site only)

Two NFS shares are required for AIDE Enterprise dark site deployments. They may reside on the same NFS server but must use different export paths.

[cols="1,1,2",options="header"]
|===
|Share |Access |Purpose

|Charts and catalog share
|Read-only (uid 1001 / gid 4321)
|Holds Helm charts and the version catalog file from the offline bundle. The AIDE operator reads charts and the catalog from this share throughout the deployment lifecycle.

|AIDE data share
|Read/write (uid 4321)
|Holds AIDE configuration and operational data. Must be writable by the AIDE services.

|===


[#dark-site-staging-host]
=== Staging host

An internet-connected staging host is required to download the offline bundle from the NetApp Support Site. The staging host does not need to be the AI Data Engine host or within the air-gapped network. Ensure the staging host has sufficient disk space for the bundle.
