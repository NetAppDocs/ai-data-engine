= Deploy AI Data Engine for dark sites
:icons: font
:imagesdir: ../media/

[.lead]
Deploy AI Data Engine in a fully air-gapped environment using the NetApp-provided offline bundle. No outbound internet access is required from the AI Data Engine host after the bundle is transferred to your environment.

Both AIDE Lite and AIDE Enterprise support dark site deployment. The bundle contains all container images, Helm charts, catalog, and installation scripts needed to complete the installation offline.

.Before you begin

Prerequisites differ between AIDE Lite and AIDE Enterprise:

[cols="1h,2,2",options="header"]
|===
| |AIDE Lite |AIDE Enterprise

|Infrastructure
|Single Linux VM meeting link:requirements.html#aide-lite-requirements[Lite sizing requirements]. The installer bootstraps k3s automatically from the bundle.
|Customer-provisioned Kubernetes cluster meeting link:requirements.html#aide-enterprise-requirements[Enterprise node requirements]. The cluster must be running before you begin.

|Access
|Root or sudo access on the target VM
|`kubectl` with `cluster-admin` privileges and Helm 3.12 or later on the install host

|Container images
|No action required. The installer preloads all container images from the bundle directly into the local container runtime.
|You must push all container images from the bundle to your private container registry before running the installer. Images pass through your organization's security scanning and approval process.

|NFS shares
|Not required.
|Two NFS shares are required, on different paths. See link:requirements.html#dark-site-nfs-requirements[NFS share requirements] for share purpose, access mode, and mount details.

|===

The following apply to all dark site deployments:

* A NetApp Console Connector must be deployed on your local network and reachable from the AI Data Engine host or cluster nodes. The installer communicates with the Connector at `http://<connector-ip>`.
// Mode docs link — replace with the correct Connector install link when available.
* _Organization admin_ or greater permissions in NetApp Console.
* An internet-connected staging host to download the bundle. See link:requirements.html#dark-site-staging-host[Staging host] for details.
* Review link:requirements.html[Requirements] and confirm your environment meets all sizing and networking prerequisites for dark site deployments.

.Steps

. Obtain the AI Data Engine dark site bundle for your release from NetApp.
+
The bundle file is named `<VERSION>_aide_darksite_bundle.tar.gz`.

. Verify the bundle integrity using the verification script included in the bundle:

.. Unpack the bundle:
+
[source,bash]
----
tar -xzf <VERSION>_aide_darksite_bundle.tar.gz
----

.. Change directory:
+
[source,bash]
----
cd aide-darksite-<VERSION>
----

.. Run the verification script:
[source,bash]
+
----
./scripts/verify-bundle.sh
----
+
The script checks every artifact against the checksums in `manifest.json` and fails with a clear message if anything is missing or corrupted. The installer also runs this check automatically before touching your system.

. Transfer the bundle to your air-gapped environment using USB media, SCP over a jump host, or your organization's preferred secure transfer method.

. On the target host (Lite) or install host with `kubectl` access (Enterprise), extract the bundle if you have not already done so:

.. Unpack the bundle:
+
[source,bash]
----
tar -xzf <VERSION>_aide_darksite_bundle.tar.gz
----

.. Change directory:
+
[source,bash]
----
cd aide-darksite-<VERSION>
----
+
Confirm that the extracted bundle includes the following directories: `installer/`, `charts/`, `images/`, `k3s/` (Lite only), `tools/`, and `scripts/`.

. Run the installer for your edition:
+
* *AIDE Lite*:
+
Single server, fully self-contained
+
[source,bash]
----
sudo ./installer/install-lite.sh \
  --darksite \
  --flavor small \
  --env production \
  --cm-host <connector-ip> \
  --account-id <account-id> \
  --organization-id <organization-id> \
  --agent-id <agent-id>
----
+
* *AIDE Enterprise*
+
Against your cluster, registry, and NFS shares:*
+
[source,bash]
----
sudo ./installer/install-enterprise.sh \
  --darksite \
  --flavor large \
  --env production \
  --cm-host <connector-ip> \
  --account-id <account-id> \
  --organization-id <organization-id> \
  --agent-id <agent-id> \
  --image-registry <registry-host>:<port>/<prefix> \
  --registry-username <username> \
  --registry-password <password> \
  --kubeconfig /etc/kubernetes/admin.conf \
  --nfs-server <nfs-server-host> \
  --nfs-data-share /exports/aide/config \
  --charts-nfs-share /exports/aide/charts
----
+
The installer verifies the bundle, stages content, installs the AIDE operator from the local bundle, and applies all required custom resources automatically. No internet access is attempted at any point.

. Monitor the operator pod until it reports `Running`:
+
[source,bash]
----
kubectl -n aide get pods -w
----

. Confirm that all components are deployed:
+
[source,bash]
----
kubectl get aidecomponents,aideservices -n aide
----
+
All rows should show `Deployed=True`. If a component shows an error, the status message names the exact missing file or blocked source.

.Result
AI Data Engine is deployed in your air-gapped environment and connected to NetApp Console through your on-prem Console Connector. You can now link:../data-sources/connect-data-source.html[connect a storage system] to start scanning.

== Upgrade a dark site deployment

Upgrades are delivered as new bundle media. The system upgrades itself automatically after you stage the new content and no reinstallation is required.

Stage content in the following order. The catalog file must be replaced _last_ because it is the trigger the operator polls.

.Steps
. Stage new container images:
** *Lite:* Load the new images from the bundle onto the server.
** *Enterprise:* Push the new images to your private registry.
+
NOTE: The new operator image must be staged before you replace the catalog file. The upgraded operator pod cannot start until its image is available.

. Copy new Helm charts from the bundle onto the charts mount or NFS share. Keep the previous version files as they are retained for rollback.

. Replace the catalog file atomically. Use the helper script included in the bundle:
+
[source,bash]
----
./scripts/drop-upgrade-content.sh
----
+
The script performs all three steps in the correct order. You can also run the steps manually, but you must follow the same sequence.
+
Within approximately 30 minutes, the AIDE operator detects the new catalog, upgrades all components in the correct rollout order, and upgrades itself. Running the upgrade script again with the same version has no effect.

. Verify that the upgrade completed:
+
[source,bash]
----
kubectl get aidecomponents,aideservices -n aide
----
+
All rows should show `Deployed=True` at the new version.
