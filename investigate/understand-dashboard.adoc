= Assess storage health with the AI Data Engine dashboard
:icons: font
:imagesdir: ../media/

[.lead]
Before you can decide what to investigate, you need to understand the state of your storage. How much storage is cold, how much stale, and which systems or owners have the most to gain from a cleanup? For example, a storage administrator responding to a capacity alert can see that a large portion of scanned storage is cold data, then drill into the highest-impact system to start investigating immediately.

From NetApp Console, select *Governance* > *AI Data Engine UI*. The Overview page opens by default.

== Understand how much storage is affected

The summary panel shows the scale of the problem across your scanned environment:

* *Cold data*: Storage not accessed within the cold data threshold (default: one year). This is your highest-confidence reclamation target.
* *Stale data*: Storage not accessed or modified within the stale data threshold (default: three years). Stale data is often safe to archive or delete but warrants review before action.
* *Exposed directories*: Directories with overly permissive access settings. These represent a governance risk independent of storage consumption.
* *Data resources*: The count of volumes, shares, and buckets currently scanned.
* *Total files scanned*: The total number of files indexed across all scanned data resources.

Cold and stale thresholds reflect your configured settings and can be changed in *Configuration* > *Settings*. Refer to link:../administer/configure-settings.html[Configure cold and stale data thresholds].

The *Active versus reclaimable storage* chart shows the proportion of active data compared to cold and stale data across all scanned resources. A high proportion of reclaimable storage indicates significant reclamation opportunity across the environment.

The *System* and *System type* filters control dashboard scope. If a storage system does not appear in the filter list, refer to link:../data-sources/connect-data-source.html[Connect a data source].

== Identify storage optimization opportunities

Use the summary panel and chart to identify and prioritize reclaimable storage:

* Start with the resource that has the largest reclaimable size, not the largest total size. A small system that is mostly cold data is often a better first target than a large system that is mostly active.
* Look for large concentrations of cold or stale data rather than isolated files. Tens of terabytes of stale data on one resource justifies an investigation; a single stale file does not.

== Move from the dashboard to investigation

When you have identified a resource or owner worth investigating, use the tables at the bottom of the Overview page to transition directly into the details.

The *Top data resources by reclaimable storage* table lists your scanned storage resources ranked by reclaimable storage. Select any row to open the Investigation view filtered to that resource. From there, use the link:investigate-unstructured.html[Unstructured] tab to identify cold or stale files, or the link:investigate-directories.html[Directories] tab to audit permission exposure.

The *Top data owners by reclaimable storage* table shows which data owners hold the largest amount of reclaimable storage. Select any row to open the link:investigate-unstructured.html[Investigation] view filtered to that owner's files. From there, you can review, act on, or save results as a policy.
