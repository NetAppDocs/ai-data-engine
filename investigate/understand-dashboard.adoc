= Assess storage health with the AI Data Engine dashboard
:icons: font
:imagesdir: ../media/

[.lead]
Before you can decide what to investigate, you need to understand the state of your storage. How much storage meets your organization's cold and stale classification thresholds, and which systems or owners hold the most data in these categories? For example, a storage administrator responding to a capacity alert can see that a large portion of scanned storage is cold data, then drill into the highest-impact system to start investigating immediately.

From NetApp Console, select *AI data hub* > *AI Data Engine*. The dashboard opens by default. The dashboard organizes its insights into three tabs: *Storage optimization*, *Access exposure*, and *Structured data*.

== Understand how much storage is affected

The summary panel shows the scale of the problem across your scanned environment:

* *Data resources*: The count of volumes, shares, and buckets currently scanned.
* *Items scanned*: The total number of items indexed across all scanned data resources.
* *Cold data*: Storage not accessed within the cold data threshold (default: one year). Your organization can evaluate this data according to your retention and governance policies.
* *Stale data*: Storage that hasn't changed within the stale data threshold (default: three years). Stale data could warrant review according to your organization's data lifecycle policies before deciding on actions such as archival or deletion.
* *Exposed directories*: The number of directories with overly permissive access settings and their associated file count. These represent a governance risk independent of storage consumption.

Cold and stale thresholds reflect your configured settings and can be changed in *Configuration* > *Settings*. The default values are product defaults and don't represent legal, compliance, or industry-standard retention periods. Refer to link:../administer/configure-settings.html[Configure cold and stale data thresholds].

The *System* and *System type* filters control dashboard scope. If a storage system doesn't appear in the filter list, refer to link:../data-sources/connect-data-source.html[Connect a data source].

The *Last updated* timestamp shows when the dashboard data was last refreshed. Select *Refresh* to update the dashboard. To confirm that the underlying data is current, refer to link:../data-sources/monitor-scanning-health.html[Monitor scanning health].

== Identify storage optimization opportunities

The *Storage optimization* tab helps you identify opportunities to reclaim storage. It includes the following charts and tables:

* _Active versus reclaimable storage_: Shows the proportion of active data compared to cold and stale data across all scanned resources. A high proportion of cold, stale, or duplicated data could indicate a significant storage optimization opportunity.
* _Top data resources by reclaimable storage_: Shows the data resources with the most reclaimable capacity.
* _Top consumers by reclaimable storage_: Shows data owners, their reclaimable storage, and their file counts.
* _Duplicate size distribution_: Shows how duplicate data is distributed across size ranges.
* _Age of assets_: Shows items by age. Use the dropdown to select the timestamp criterion for the chart.
* _Top file types_: Shows the most common file types.

Use the summary panel and these charts to identify and prioritize storage optimization opportunities:

* Focus on resources that have the largest potentially reclaimable size, rather than those with the highest total size. A small system that is mostly cold or stale data might be a better first resource to evaluate than a large system that is mostly active.
* Look for large concentrations of cold or stale data rather than isolated files. Tens of terabytes of data meeting your stale threshold on one resource warrants evaluation; isolated files might not require action.

== Review access exposure

The *Access exposure* tab shows the _Directories with open permissions_ chart, which lists directory paths and their file counts. Use this view to identify directories to prioritize for a permissions review. To see these directories in detail, refer to link:investigate-directories.html[Investigate directories].

== Explore structured data

The *Structured data* tab shows the _Structured data summary_ table, which lists the schema, database table name, and number of rows. Use it to identify the schemas and tables represented in your scanned data and compare their row counts. To search and filter this data, refer to link:investigate-structured.html[Investigate structured data].

== Move from the dashboard to investigation

When you have identified a resource or owner worth investigating, use the tables on the *Storage optimization* tab to transition directly into the details.

The _Top data resources by reclaimable storage_ table lists your scanned storage resources ranked by the proportion of data that is duplicated or meets your organization's cold and stale thresholds. Select any row to open the Investigation view filtered to that resource. From there, use the link:investigate-unstructured.html[Unstructured] tab to identify cold or stale files, or the link:investigate-directories.html[Directories] tab to audit permission exposure.

The _Top consumers by reclaimable storage_ table shows which data owners own data that is potentially reclaimable. Select any row to open the link:investigate-unstructured.html[Investigation] view filtered to that owner's files. From there, you can review results, act on them, or save them as a policy.

Reviewing the dashboard doesn't archive or delete data or change directory permissions.
