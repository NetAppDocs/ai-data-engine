= Learn about the AI Data Engine dashboard
:icons: font
:imagesdir: ../media/

[.lead]
Before you investigate individual files, use the Overview page to see how much of your storage could be better optimized and where. This page is your entry point into AI Data Engine. You'll understand where to look for storage improvements and narrow your investigation.

For example, a storage administrator responding to a capacity alert can see that a significant portion of scanned storage is cold data, then drill into the highest-impact system to start investigating immediately.

From NetApp Console, select *Governance* > *AI Data Engine UI* and the Overview page opens by default. The *System* and *System type* filters control dashboard scope, reflecting storage systems that have been registered through the NetApp Console Agent and enabled for scanning. If a storage system does not appear in the filter list, see link:../data-sources/connect-data-source.html[Connect a data source].

== What the dashboard tells you

The Overview page shows how much storage exists across your environment, how much of it is cold or stale, and where it is concentrated. The summary panel and chart give you the numbers; the resource table tells you where to focus.

== Summary panel

The summary panel shows these metrics for your scanned environment:

* *Data resources*: The count of volumes, shares, and buckets currently scanned.
* *Total files scanned*: The total number of files indexed across all scanned data resources.
* *Cold data*: Storage not accessed within the cold data threshold (default: 3 years).
* *Stale data*: Storage not accessed or modified within the stale data threshold (default: 1 year).
* *Exposed directories*: Directories with overly permissive access settings detected during scanning.

Cold and stale thresholds reflect your configured settings and can be changed in *Configuration* > *Settings*.

== Active versus reclaimable storage chart

The *Active versus reclaimable storage* chart shows the proportion of active data compared to cold and stale data across all scanned resources. The combined size of cold and stale data is your total reclaimable storage. Use this chart to assess overall storage efficiency.

== Identify storage optimization opportunities

Use the summary panel and chart to prioritize storage optimization opportunities:

* Start with the resource that has the largest reclaimable size, not the largest total size. A small system that is mostly cold data is often a better first target than a large system that is mostly active.
* Look for large concentrations of cold or stale data rather than isolated files. Tens of terabytes of stale data on one resource justifies an investigation; a single stale file does not.

== Drill down from a dashboard finding into investigation

After you identify a resource worth investigating, use the *Top data resources by reclaimable storage* table to move from the overview to the details.

This table lists your scanned storage resources ranked by reclaimable storage. Click any row to open the link:investigate-data.html[Investigation] view filtered to that resource.

== Identify data owners with the most reclaimable storage

The *Top data owners by reclaimable storage* table shows which data owners hold the largest amount of reclaimable storage across your environment.

Click any row to open the link:investigate-data.html[Investigation] view filtered to that owner's files. From there, you can review, act on, or save results as a policy.

== Refresh and explore further

* Click *Refresh* to update the page with the latest scan data. The last-updated timestamp appears on the page.
