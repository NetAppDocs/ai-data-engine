= Take action on your data in AI Data Engine
:icons: font
:imagesdir: ../media/

[.lead]
Enforce your organization's data lifecycle policies by acting on the files you identified with your filters. For example, a storage administrator who filters to find terabytes of VM snapshots not accessed in over a year can archive them in bulk to a cold storage share, or delete them, depending on retention requirements and business policies.

.About this task
To take action, select one or more items in the Investigation results table using the checkboxes. The action toolbar activates with four options: *Delete*, *Archive*, *Copy*, and *Tag*. To remove duplicate copies of a file, use *Clean up duplicates*. Refer to <<Investigate and clean up duplicate files>>.

== Decide what to do

Choose an action based on how certain you are about the data:

[cols="1,2",options="header"]
|===
|Action |When to use it

|Tag
|You need more time, or need to coordinate with another team, before committing to archive or delete. Tagging tracks the files without changing their location.

|Archive
|The data might still have value, but it doesn't belong in primary storage. Archiving moves it to a lower-cost destination while keeping it recoverable.

|Copy
|The data should exist in a second location, for example for backup or migration purposes. Copying preserves the original in place. You can copy to an NFS or SMB folder, create a filtered FlexClone volume, or transfer items with Cloud Sync.

|Delete
|The data is no longer needed and has no retention requirements. Deletion is permanent, so use it only when you are sure.

|===

When data might still have value or require further review, choose tagging, archiving, or copying over deleting. Only delete when you are certain the data is safe to remove permanently.

== Archive files

Move files that don't belong in primary storage to a cold storage destination while keeping them recoverable. You can optionally leave a breadcrumb file at the original location so that users can tell why a file was moved.

CAUTION: Copying or archiving files can change destination permissions, ownership, group information, and timestamps. Cross-protocol transfers can substantially broaden access. Review the destination security settings before transferring sensitive data, and verify permissions afterward.

NOTE: The credentials you provide for an SMB destination are separate from the Active Directory integration. To display user names and permissions in AI Data Engine, refer to link:../administer/configure-settings.html[Configure data classification thresholds and access scanning].

.Before you begin
* You must have the _AI Data Engine administrator_ role.

.Steps
. In the Investigation view, select the files you want to archive.
. Select *Archive*.
. In the Archive dialog, select the destination volume protocol:
+
* For *NFS*, enter the destination folder path in the format `hostname:/path/to/destination`.
* For *SMB*, enter the SMB destination folder path in the format `\\Hostname\share_name`. Select the authentication method. For Kerberos, use the FQDN of the host and leave the credentials empty. Refer to link:../administer/configure-kerberos-smb.html[Kerberos authentication for SMB/CIFS shares in AI Data Engine]. For other methods, provide Active Directory credentials: enter the username in `domain\user` or `user@domain` format, and enter the password.

. To create a breadcrumb file at the original location, enable *Leave breadcrumb*.
+
A breadcrumb file helps users understand why a file was moved.
. Select *Archive*.

== Copy selected items

Make selected items available in another location, for example, for backup or migration. You can copy items to an NFS or SMB folder, create a filtered copy of an ONTAP volume, or transfer items using Cloud Sync.

Choose the method that matches your goal:

* *Regular copy*: Copy items to an NFS or SMB destination folder without changing the original files.
* *FlexClone*: Create a point-in-time copy of an ONTAP volume and remove items that were not included in your query from the cloned volume. The original volume is not affected.
* *Sync*: Transfer items between file or object storage, on premises or in the cloud, using Cloud Sync.

.Before you begin
* You must have the _AI Data Engine administrator_ role.

.Steps
. In AIDE, select *Investigation* from the left navigation.
. Use filters to find the items you want to copy, and then select the items in the results table.
. Select *Copy*.
. Complete the procedure for your chosen copy method.

=== Copy items to an NFS or SMB folder

Use regular copy to place copies of selected items in a destination folder while leaving the original files unchanged.

CAUTION: Copying or archiving files can change destination permissions, ownership, group information, and timestamps. Cross-protocol transfers can substantially broaden access. Review the destination security settings before transferring sensitive data, and verify permissions afterward.

.Before you begin
* Ensure that the destination share allows access from the AI Data Engine. NFS and SMB shares are supported regardless of where they are hosted.
* For an SMB destination, have Kerberos or NTLM credentials available.

.Steps
. In the *Copy selected items* dialog, select *Regular copy*.
. Choose the destination protocol and provide the destination details:
+
* For *NFS*, enter the destination folder path in the format `hostname:/path/to/destination`.
* For *SMB*, enter the destination folder path in the format `\\hostname\share_name`. Specify the SMB authentication type as Kerberos or NTLM and enter the password when prompted. For Kerberos, use the FQDN of the host and leave the credentials empty. Refer to link:../administer/configure-kerberos-smb.html[Kerberos authentication for SMB/CIFS shares in AI Data Engine]. For other methods, provide Active Directory credentials: enter the username in `domain\user` or `user@domain` format, and enter the password.

. Review how copying might affect file metadata:
+
* Permissions, ownership, and group information might be preserved when possible. If source identities cannot be mapped, destination defaults might apply.
* Source timestamps, including creation time, might not be preserved and might reflect the copy operation or destination behavior.
* New directories use the destination's default permissions.
* Cross-protocol transfers can broaden access. Review the destination's security settings before copying and verify permissions afterward.

. Select *Submit*.

=== Create a filtered copy of an ONTAP volume

Create a cleaned-up copy of an ONTAP volume that contains only the items in your query, ready to migrate. FlexClone creates a point-in-time copy of the volume and deletes the items outside your query from the clone only.

.Before you begin
Ensure that all selected items belong to the same ONTAP volume. The FlexClone volume is created in the same aggregate as its parent volume.

.Steps
. In the *Copy selected items* dialog, select *FlexClone*.
. Enter a *Name* for the cloned volume.
. Confirm that your query includes all the items you want to retain in the cloned volume.
+
Items not included in the query are deleted from the clone. The original volume is not affected.
. Select *Submit*.

=== Transfer items using Cloud Sync

Transfer selected items between file or object storage locations, on premises or in the cloud.

.Before you begin
Ensure that all selected items belong to the same storage repository. If your selection spans repositories, cancel the operation and select items from a single repository.

.Steps
. In the *Copy selected items* dialog, select *Sync*.
. Review the number of items to be synced and confirm that it matches the items you intend to transfer.
. Select *Sync* to proceed with Cloud Sync.

== Delete files

Permanently remove files that you no longer need and that have no retention requirements.

CAUTION: Deletion is permanent and can't be undone. This action deletes source files even if they contain active data.

.Before you begin
* You must have the _AI Data Engine administrator_ role.

.Steps
. In the Investigation view, select the files you want to delete.
. Select *Delete*.
. In the Delete dialog, type *permanently delete* in the confirmation field.
. Select *Delete*.

.Result
The selected files are permanently deleted from storage.

== Investigate and clean up duplicate files

Find duplicate copies of a file and remove the redundant ones. Review the copy metadata and locations, and tag duplicates for review, archive them, or permanently delete duplicate copies while retaining one copy.

.Before you begin
* You must have the _AI Data Engine administrator_ role.

.Steps
. In NetApp Console, go to *AI data hub* > *AI Data Engine*.
. Select *Investigation* > *Unstructured*.
+
The table displays file names, sizes, owners, systems, and tags.
. Optional: Select *Add filter* to narrow the list of files.
. Select a file name to open its details.
+
Review the file's system, storage repository, path, size, timestamps, access, and owner. The *Duplicates* field displays the number of duplicate copies.
. Next to *Duplicates*, select *View details*.
+
The Investigation view applies a *Duplicates* filter that includes files with duplicates and a *File hash* filter that matches the selected file.
. Review the matching files and their locations.
. Select the files you want to clean up.
+
Review the *Selected items* count. To start again, select *Clear selection*.
. Select *Clean up duplicates*.
. Review the estimated number of files matching the current filters that have duplicate copies.
+
NOTE: The count is an estimate. Exact duplicates are recalculated when the action runs, and only files confirmed identical are affected.
. Decide how to handle the duplicates:
+
* Tag the duplicates for review:
.. Under *Action*, select *Tag*.
.. Select *Add*, and then choose the tag to apply. Repeat to add more tags.
.. Select *Submit*.
* Archive the duplicates to a destination volume:
.. Under *Action*, select *Archive*.
.. Under *At the original location*, select *Remove cleanly* or *Leave a breadcrumb*.
.. Select the destination volume protocol. For *NFS*, enter the destination folder path in the format `Hostname:/SHAREPATH`. For *SMB*, enter the destination folder path, and then select *Kerberos* or *NTLM* authentication. For NTLM, enter your Active Directory user name and password.
.. Select *Submit*.
* Delete the duplicates and keep one copy:
+
CAUTION: Deletion is permanent and can't be undone.

.. Under *Action*, select *Delete*.
.. Under *Keep copy with the*, select *Last accessed*, *Last modified*, or *Created*.
.. Under *At the original location*, select *Remove cleanly* or *Leave a breadcrumb*.
.. Select *Submit*.
.. In the *Delete the duplicate copies* dialog, review the number of files to be deleted and the information about retaining one copy.
.. Enter `permanently delete`, and then select *Delete*.

To exit without submitting an action, select *Cancel*.

== Tag files

Track files that you want to revisit or coordinate on with another team, without changing their location. For example, apply an "Archive candidate" tag to identify files that require review before you archive or delete them.

.Steps
. In the Investigation view, select the files you want to tag.
. Select *Tag*.
. Enter or select the tags to apply (for example, "Archive candidate").
. Confirm to apply the tags.
